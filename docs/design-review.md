# Screen Pin 设计复核记录

复核目标：在已确认 Q1–Q18 的范围内，让第一次配置容易成功、日常操作可预测、后台占用低，并将可靠性落实为可检验约定。本文保留设计阶段的发现；改进已进入原生实现，当前测试及待验收项见 [阶段记录](validation/phase-6.md) 和 [需求覆盖审计](validation/coverage.md)。

## 发现及处理

| 原设计缺口 | 可能产生的结果 | 本次修订 |
| --- | --- | --- |
| 首次运行仅驻留托盘 | 用户以为没启动，不知道怎样建立首个预设 | 首次显式启动展示主界面与三步说明；后续驻留托盘 |
| 当前窗口未明确排除临时对话框 | “另存为”位置覆盖整个应用默认预设 | 限定可独立布置窗口，临时对话框拒绝且不转向背后主窗口 |
| 标题变化回退默认的影响不显眼 | 用户以为只修改一个窗口，实际更新应用共享位置 | 预览及结果显示作用范围；一级撤销入口；无变化不替换撤销记录 |
| 查看方案与活动方案混在一起 | 用当前环境窗口覆盖未连接环境配置 | 明确两种概念，离线方案只读，热键始终使用活动方案 |
| 屏幕关联只有提示没有可辨认流程 | 同型号屏幕被关联反，短暂拓扑产生多余方案 | 稳定拓扑后处理；识别屏幕标记；一对一关联统一提交 |
| 只规定比例和 PMv2，没有边框及还原坐标契约 | 反复捕获恢复漂移，最大化还原到错误屏幕 | 以可见外框定义比例，区分外框和还原矩形；增加连续 20 次验证 |
| 全部应用按 EXE 路径识别 | 打包应用升级后失配，宿主进程误合并 | 传统桌面路径与可靠包应用身份分开，拒绝未知宿主归属 |
| 文件原子替换未覆盖运行状态 | 保存失败后磁盘与内存不一致，撤销覆盖新修改 | 单一提交入口，持久化成功再发布；撤销按原目标和版本处理 |
| 热键修改、长按和排队语义不足 | 原热键丢失或多次覆盖撤销，操作到新前台窗口 | 注册与映射分离、保留旧注册、MOD_NOREPEAT、固定目标与版本、忙时不积压 |
| 只有有界队列，没有外部请求时限和结果分类 | 一个挂起窗口拖住工具，异步请求误报取消 | 有界执行及结果验证，区分受限和未确认，不承诺撤回已发请求 |
| 普通单实例与提权重启未协调 | 两份配置、两个写入者或旧实例提前退出 | 同账号及会话限定，明确接管握手、时限和回退 |
| “原生”“轻量”缺少验收依据 | 无障碍差、字体截断、资源持续增长仍被视为完成 | 键盘／Narrator／缩放验收、响应与资源预算、干净环境 ZIP 验证 |

## 范围与取舍

保留两个热键、手动恢复及更新、应用默认与标题规则、每组合一个方案、物理屏身份、比例几何、普通及最大化、托盘、GUI、撤销、按需提权、ZIP 和本地保存。首次主界面、可理解反馈与关联流程补齐已有功能的操作闭环。

继续采用 Rust／Win32 的设计基线，但不能仅因本机已有工具链就推定界面品质或发布可用。先验证几何、屏幕身份与提权交接三处风险；只保留少量模块，由一个操作协调模块包含关键时序规则。没有增加云同步、插件、自动窗口整理或复杂布局编辑器。

几何约定影响持久格式，已补充 [ADR 0001](adr/0001-relative-work-area-placement.md)；物理显示器决策继续沿用 [ADR 0002](adr/0002-physical-display-identity.md)。其余属于已有需求的具体行为和质量约定，不逐项新增 ADR。

## 完成情况

- 已完成交互、可靠性及 Windows 约束三方面独立复核并合并改进。
- 已建立可检查的质量门槛，并按实际证据区分已验证、局部验证及未验证；完整门槛继续有效。
- 设计改进及后续实现不等于最终验收通过；应用品质仍须由对应交互、硬件和发布验证结果证明。
