# Screen Pin 首版设计

状态：Q1–Q18 的产品决定已保留；本版为复核后的设计基线，实现与分阶段验收正在进行，整体实机验收尚未完成。复核依据见 [design-review.md](design-review.md)，发布门槛见 [acceptance.md](acceptance.md)，当前证据见 [阶段 12](validation/phase-12.md)。

## 1. 定位与范围

Screen Pin 是 Windows 11 x64 上的个人窗口布局工具。用户摆好窗口后记住位置，之后用热键恢复当前窗口；单屏与多屏均适用。

- 两个日常动作：恢复位置、记住位置。界面中“记住位置”对应领域中的创建或更新预设。
- 每次操作一个窗口；应用启动、显示器切换和方案自动选择均不自动移动窗口。
- 每种物理显示器组合一个方案；每个应用一个可选默认预设，加有序的标题关键字规则。
- 提供系统托盘、基础配置界面、免安装 ZIP、本地配置，以及默认关闭的可选开机启动。
- 首版采用窗口捕获与表单编辑；同一组合多方案、拖拽布局编辑器、自动整理全部窗口不纳入首版。
- 技术复杂性留在程序内部；普通使用不要求理解坐标单位、设备路径或窗口句柄。

## 2. 首次使用与日常流程

首次显式启动打开主界面，并同时创建托盘入口。主界面直接展示“摆好窗口 → 记住位置 → 移动后恢复”的短说明和当前有效热键，不增加独立向导。没有预设时，唯一主要操作是“选择窗口并记住位置”；用户也可切到目标窗口直接按热键。

后续启动驻留托盘。关闭主界面继续运行；托盘提供打开主界面、撤销最近一次更新、管理员重启和退出。重复启动打开现有实例的界面。

| 动作 | 默认热键 | 行为 |
| --- | --- | --- |
| 恢复位置 | Ctrl+Alt+F9 | 恢复触发时窗口的匹配预设；无预设只提示 |
| 记住位置 | Ctrl+Alt+F10 | 捕获当前显示器、位置、大小及普通或最大化状态，更新匹配预设或创建应用默认 |

反馈不抢焦点、不激活工具自身、不改变窗口层级；用户后续输入继续送达原窗口。恢复一个已经符合预设的窗口不重复移动。

## 3. 可配置窗口与应用身份

热键使用触发时锁定的外部前台窗口；主界面使用列表中明确选择的窗口。打开主界面后，不再用工具自身这个前台窗口替代已选择的目标。

- 支持可独立布置的普通应用窗口。
- 桌面、任务栏、工具自身、临时菜单、工具提示、文件选择等临时对话框不作为预设目标；拒绝时说明原因，不能暗中改为操作背后的主窗口。
- 最小化不作为目标状态保存。窗口列表明确标示最小化或其他不可捕获状态；要求用户恢复后再捕获。
- 全屏或疑似全屏窗口跳过并提示；检测先区分正常最大化，避免把任务栏自动隐藏时的最大化误认为全屏。
- 普通桌面应用用规范化的完整可执行文件路径识别。同名但路径不同的应用不自动合并，路径变更可以重新选择应用修正规则归属。
- 可靠取得真实打包应用身份时，以包族及清单应用 ID 识别，避免仅因包版本更新而失配。不能把任意窗口级 AppUserModelID 当作应用身份，也不能把无法确定归属的宿主进程下所有窗口合并。
- 标题差异交给用户配置的特定窗口规则，不尝试推测浏览器账号、profile 或文档身份。

打包应用身份依据：[包身份概述](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/package-identity-overview)、[GetApplicationUserModelId](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getapplicationusermodelid)、[AppUserModelID 作用范围](https://learn.microsoft.com/en-us/windows/win32/shell/appids)。

## 4. 方案、规则与更新目标

“活动方案”始终由当前显示器组合决定。主界面正在查看的其他方案不会改变它；首版非活动方案只读，明确标为“未连接／仅查看”。捕获和热键更新只能写入活动方案。

每个应用先按用户排序查找标题规则，第一条匹配规则胜出；没有特定规则匹配时回退应用默认。关键字采用不区分大小写的包含匹配，禁止空关键字。新建特定规则放在列表末尾，显示匹配预览；同应用相同关键字提示重复，有交叠时说明实际获胜规则，允许用户调整顺序。

| 匹配结果 | 恢复位置 | 记住位置 |
| --- | --- | --- |
| 特定规则 | 使用该规则的预设 | 更新该预设 |
| 仅应用默认 | 使用默认预设 | 更新默认预设 |
| 无预设 | 提示尚未配置及记住位置的热键 | 创建活动方案下的应用默认预设 |
| 已匹配规则的目标屏未关联 | 提示先关联屏幕 | 暂停更新，保留配置 |
| 窗口不合格或采样失败 | 提示原因 | 不创建、不覆盖 |

两个操作共用匹配逻辑；已匹配但暂不可用的规则不能被越过后改写其他预设。特定规则只通过主界面明确创建。

标题变化后仍按上述规则回退默认；不增加每次更新的确认框。默认被更新时，反馈必须明确“应用默认，同应用窗口共用”，并提供容易找到的撤销入口。更新本身不移动同应用其他窗口。

## 5. 显示器组合与关联

显示器组合是当前参与桌面的物理显示器集合。数量相同不代表同一组合；排列、分辨率、缩放变化不创建新方案。预设跟随物理屏幕，而不是左右位置或临时编号。

显示变化采用短暂合并与重新枚举，拓扑稳定后才选中或建立方案；插拔、唤醒过程中的中间状态不持久化为空方案。

- 确定是新组合：建立空方案，保留旧方案。
- 无法确定是否旧组合或存在身份冲突：进入待关联状态，保留原配置。若活动方案本身不确定，暂停全部窗口恢复与捕获；若方案已唯一确定、仅部分目标屏待关联，只暂停受影响预设。配置查看、设置和关联入口继续可用。
- 变化处理中：显示“正在识别显示器，请稍后重试”，不排队保存到未知方案。
- 为物理屏保存内部 ID 与多项识别证据。设备路径、接口、厂商型号和可用序列号都只是证据；证据冲突、缺失或重复时不猜测对应关系。

关联页提供“识别屏幕”，在各实际屏幕短暂显示编号，并展示名称、分辨率和相对位置。用户将旧目标与当前屏幕一对一关联，检查受影响预设后统一应用；取消不写入半完成映射。临时编号只辅助辨认。

取舍见 [ADR 0002](adr/0002-physical-display-identity.md)。系统提供字段的范围见 [DISPLAYCONFIG_TARGET_DEVICE_NAME](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-displayconfig_target_device_name)。

## 6. 几何与窗口状态的明确约定

普通窗口以用户可见的窗口外框为布局对象，包含标题栏和可见边框，排除不可见调整边框；位置和大小分别相对目标屏可用工作区原点及宽高保存为比例。任务栏等系统保留区域不计入工作区。数据保留完整比例精度，界面显示的百分比舍入不反写原值。

- 内部统一屏幕物理像素；可见边界、系统窗口外框和 WINDOWPLACEMENT 还原矩形必须经过适配层转换，不能混用。
- 进程声明 PerMonitorV2；DPI 感知不能替代上述坐标转换。
- 普通和最大化是独立目标状态；最大化预设另外保留正常还原矩形。捕获最大化窗口时不临时还原用户窗口，也不把最大化矩形记成普通尺寸。
- 跨屏窗口以交叠面积最大的显示器为基准，保存实际比例；完全离屏或不再可操作时作最小可见性修正，并报告受限结果。
- 恢复最大化窗口时正确设置目标屏上的还原位置及最大化状态；之后用户点击还原仍应落在目标屏。
- 应用最小尺寸、跨 DPI 自行调整等以实际结果核对，不把偏差自动覆盖为预设。

比例语义见 [ADR 0001](adr/0001-relative-work-area-placement.md)。[GetWindowRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect) 与 [WINDOWPLACEMENT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement) 的坐标及边框差异是必须验证的实现约束。

## 7. 界面、反馈与撤销

主界面以“当前环境＋窗口列表＋记住位置”为主要层级。方案管理、标题规则和百分比编辑位于对应预设的编辑区域；显示器关联仅在需要时出现，设置包含热键、开机启动及配置位置。常见操作不要求先编辑数值。

活动方案下可创建应用默认预设或特定窗口规则，编辑目标显示器、位置与尺寸百分比、普通或最大化状态，修改关键字、调整规则顺序及删除预设。删除明确指定所选记录，不能误删同应用其他规则。

- 选中窗口后展示匹配预览；保存按钮文字说明是新建默认、更新默认还是更新特定规则。
- 百分比编辑校验有限数值和正尺寸；标明字段以可用工作区为基准。
- 预设表单未保存的编辑在恢复、无变化更新和其他记录更新后保留。同一预设未改变时可基于最新配置版本保存；同一预设已更新时保留草稿并明确提示冲突，拒绝旧草稿覆盖。此时点击刷新会放弃草稿并载入当前值；正常刷新不丢弃有效草稿。保存成功后显示已提交值；切换预设、删除或迁移目标会重新载入相应编辑区。
- 设置页的热键文本和自启勾选在恢复、刷新、查看其他方案和无关更新后保留。输入只是草稿，实际注册状态单独显示；明确保存成功后才显示已提交值。注册冲突或写盘失败保留输入供重试，原有热键继续有效；恢复备份改变实际设置时载入恢复后的值。处理操作期间以及配置保护模式下，设置字段与保存一并禁用。
- 规则排序提供上移、下移按钮；所有操作可用键盘完成，保留可见焦点和合理的 Tab 顺序。
- 使用系统字体与标准控件，支持高对比度、系统大字体和 100%／150%／200% 缩放；错误和注册状态不只依赖颜色。Narrator 能读出标签、名称和状态。
- 提示不抢焦点；短时间相同提示合并。主界面及托盘保留最近结果，系统通知被关闭时仍能查明原因。
- 恢复成功给短暂轻提示；更新显示方案、应用及规则范围。失败给下一步，例如修改冲突热键或关联显示器，不把未知错误一律归因于权限。

| 结果 | 含义与反馈 |
| --- | --- |
| 已符合／已恢复 | 状态、目标屏和几何在允许误差内 |
| 受限恢复 | 已执行，但应用约束或可见性修正使结果偏离 |
| 已记住／无变化 | 已持久保存，或当前预设内容无需改变 |
| 暂无法确认 | 请求已发出，但在时限内未确认完成；不宣称一定没移动 |
| 已取消／失败 | 尚未发出的步骤停止；保留预设并说明原因 |

撤销只恢复配置，不移动窗口。托盘一级菜单显示“撤销刚才对……的更新”，主界面也可执行。“记住位置”、GUI 捕获和预设表单保存产生的成功且有实际变化的创建或覆盖，均生成新记录并替换上一条；连续编辑同一预设时，撤销回到最后一次编辑之前。无变化、长按重复及失败不覆盖有用记录。首次创建的撤销删除该预设，覆盖的撤销恢复旧值。记录限当前会话，作用于原方案和原预设；无关设置或规则排序不影响它。删除目标、重新关联改变目标语义等结构变化使旧记录失效；执行撤销前还要核对目标版本，冲突时明确拒绝。

## 8. 热键设置与操作一致性

两个热键可修改，不能设置为同一组合；使用 MOD_NOREPEAT 抑制长按。界面同时显示保存值与实际注册状态。

热键注册按按键组合管理，命令映射单独维护：先尝试新增组合并保留旧注册，保存候选配置成功后再发布映射、释放不用的旧注册。两个热键互换只改变命令映射。注册或配置保存失败，释放临时新增注册并继续使用旧映射，其他有效绑定始终保留。重启时被外部占用的组合明确显示不可用。

所有预设、规则、关联和设置修改共用一个串行提交入口：生成候选状态 → 核对基础版本及校验 → 持久化成功 → 发布内存状态及撤销记录 → 提示成功。从核对基础版本到持久化及发布完成保持独占，过期候选须拒绝或基于最新状态重新生成；GUI 和热键不能各自提交旧快照。提交运行在后台，失败不能只保住磁盘却让运行中规则先变更。

每次操作锁定目标窗口身份、采样、活动方案、拓扑版本和相关配置版本。执行及提交前重新校验；焦点变化不会让操作改到新窗口，窗口销毁或相关状态过期时取消。标题变化导致匹配结果改变时也要求重新触发。

每次只接受一个窗口操作，忙时提示且不积压按键；托盘、退出及配置界面保持响应。对外部窗口的请求和验证有时间上限；已发出的异步请求无法保证撤回，因此取消只能阻止尚未发出的步骤。实现依据：[RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)、[IsWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-iswindow)、[SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

## 9. 配置、运行权限与生命周期

配置保存到 %LOCALAPPDATA%\ScreenPin\config.json，包含格式版本、显示器关联、方案、预设、规则和设置；不保存临时 HWND。同目录临时写入后替换有效文件，保留上一份通过校验的备份。

| 读入状态 | 行为 |
| --- | --- |
| 文件不存在 | 创建初始配置并显示首次使用入口 |
| 有效旧版本 | 备份原件，按已支持迁移升级 |
| 损坏或校验失败 | 保留原件，暂停配置写入，提供恢复有效备份或明确新建的入口 |
| 高于程序支持版本 | 保留文件并只读提示，不用旧程序覆盖新字段 |

坏文件不参与正常备份轮换；迁移、保存和恢复均需校验成功。普通退出、升级和解压覆盖程序文件不删除用户配置。

默认普通权限运行。管理员重启只支持同一用户及登录会话的提权；跨账号凭据提权不自动接管原用户配置，原实例继续可用。

正常重复启动与提权交接是两个流程。交接时旧实例先完成写入，新实例验证身份和初始化；旧实例交出热键和唯一写入权后，新实例确认接管，旧实例才退出。取消 UAC、准备失败或接管失败应有时限与回退；任何时刻只允许一个配置写入者，超时不能绕过写入锁。此流程必须实机验证。

托盘在 Explorer 重启后重建，退出释放资源。开机启动默认关闭，启用后按普通权限启动，使用带正确引号的实际可执行文件路径；程序位置改变后在设置中提示修复入口。

UAC 可能使用另一管理员账号的事实见 [UAC 工作原理](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works)。

## 10. 实现结构与开发顺序

技术基线仍为 Rust＋windows crate＋原生 Win32 控件＋JSON，发布时不要求用户另装 .NET 或 WebView。选择依据是本工具主要处理 Win32 窗口、热键和托盘，界面规模有限；原生控件仍必须通过界面和可访问性验收。

ZIP 必须在未安装开发工具链的 Windows 11 x64 环境验证，所需运行依赖须由系统或发布包提供，不能依赖开发机偶然已有的运行库。

保持少量有明确职责的模块。一个操作协调模块通过恢复、记住、编辑、撤销这些入口包含匹配、版本校验、提交及结果处理；GUI 和热键只提交意图。规则选择与比例计算保持纯逻辑。Windows 操作和文件存储作为内部 Adapter，测试使用可控 Adapter 验证失败及竞态；不建立插件框架或重复的 GUI／热键业务实现。

隐藏顶层窗口与非模态配置界面共用消息循环，外部窗口操作及写入不长时间阻塞它；空闲时事件驱动，不持续轮询所有窗口。跨进程请求须采用有界方式，有界队列本身不能替代执行超时。

1. 先完成三个小规模技术验证：混合 DPI／可见边框与最大化还原、物理显示器识别与关联、同账号提权及实例交接。
2. 打通单屏“记住 → 移动 → 恢复”及持久配置的端到端流程。
3. 加入多屏方案、标题规则、事务提交和撤销。
4. 完成主界面、关联页、热键设置及生命周期。
5. 执行 [验收与质量门槛](acceptance.md)，修正阻断问题，构建并验证 x64 ZIP。

技术验证发现方案不成立时，先修正相关设计再扩大实现；不以“使用原生控件”或“编译通过”替代品质验证。

## 11. 兼容性与交付证据

验收以本地桌面会话为准，首批样本为浏览器、文件资源管理器、VS Code、Windows Terminal、普通及管理员终端，按实机可用情况记录精确版本。

同型号屏幕、换接口和扩展坞可能需要重新关联。普通窗口尺寸、标题和全屏判断存在应用差异；结果必须如实反馈。远程桌面、镜像显示和受保护游戏窗口暂不保证。

发布记录应列出实际通过的应用与显示器组合、功能测试、性能测量和已知限制。未获得硬件或权限的项目标为未验证，不能算通过。当前已有原生实现、单元／故障注入测试及受控单屏窗口探针；不能据此推定物理多屏、混合 DPI、UAC 或干净环境已经通过。
