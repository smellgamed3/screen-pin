## 计时定义与结果

[原始报告](../../artifacts/startup/startup-d2736e125448437ab3c517bfd32ae89f/report.json)：**102 条检查、10 次已有配置启动、5 次首次启动**通过；另一个实例用于准备真实捕获的基准，**共 16 个实例正常退出**。原始样本全部保留。

计时从调用 Start-Process 前开始，包含进程创建、脚本观察及实际输入的开销。除准备基准的实例外，两种正式场景均不传 `--show` 或 `--background`，只传独立的 `--config-dir`。

| 场景 | 样本与完成时间 | 通过依据 |
| --- | --- | --- |
| 基础已有配置 | 5 次，**290.066–309.653 ms** | 1 个应用／2 条标题规则，2,845 B；托盘可定位，真实 F9 恢复并确认、真实 F10 返回无变化，全部在 1,000 ms 内 |
| 较多已有配置 | 5 次，**369.973–382.856 ms** | 20 个应用／60 条标题规则，52,135 B；相同真实操作及 1,000 ms 门槛全部通过 |
| 首次显式启动 | 5 次，界面自动显示 **302.194–316.654 ms**；直到真实键盘捕获持久化成功 **600.997–698.895 ms** | 配置原本不存在；自动显示主界面，Tab／Home／方向键选择自建窗口，Tab／Space 记住实际位置；全部在 1,500 ms 内 |

已有配置中，主界面始终隐藏、目标保持前台；10 次恢复最大边界误差 **0 px**。每次检查主配置和备份的前后 SHA256，均未改变。F9 后再用 F10 的不同反馈确认另一枚热键也确实响应，没有只凭界面的“已注册”状态下结论。

托盘就绪通过已核对 PID 的 Host HWND／uID 1 调用 Shell_NotifyIconGetRect，取得非空图标矩形；其 [官方定义](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyicongetrect) 是通知图标的屏幕边界。它证明 Shell 已能定位该图标，不要求用户把图标固定在任务栏上，也不测绘制像素。计时终点还要求两枚真实热键均完成，因此比单独的窗口消息响应提供更强的就绪证据。

首次界面中，主页面入口、窗口列表、刷新和结果字段均在客户区完整可见；无需手动刷新即有自建窗口。5 次键盘捕获的实际应用身份正确，持久化几何换算后误差均 **0 px**。本轮完成捕获的时间是“可操作”的上界，包含测试自身导航和确认开销；不把开发脚本当作新用户 60 秒易用性验收。

## 复现与观察边界

```powershell
pwsh -NoProfile -File scripts/startup-smoke.ps1
```

默认 10 次已有配置、5 次首次启动。也可通过 `-ExePath` 指定已核对哈希的解压 EXE。先按 [构建入口](phase-6.md#回归与复现) 准备 Release 及 `accessibility_probe.exe`；脚本需 PowerShell 7。

每轮开始前只通过公共 UIA 聚焦自建 fixture，之后的计时包含正式启动与实际输入。输入前和等待期间持续核对前台／进程归属，观察到外部切焦即停止输入；不绕过 Windows 前台策略。只移动自建窗口，所有配置在新测试目录；没有修改真实 HKCU Run。较大配置的额外应用身份为私有 JSON 样本，不表示同时打开了 20 款真实应用。

早期准备失败保留在 `artifacts/startup`：建立规则前未明确选择目标，以及发出键盘输入后过早读取列表状态。现在等待 Tab 焦点和每次行选择实际生效，再判断可操作性。最终完整报告无失败；这些修正不改产品行为。此前后台开关场景的测量不代替本报告的默认启动路径。

这是同一台开发机上的重复缓存启动，样本较少。报告中的 nearest-rank p95 在本次 10／5 个样本上等于各自最大值，不外推其他硬件、冷启动、任意配置规模或磁盘负载。旧的约 273 ms 消息循环代理仍只作为历史观察；启动门槛现在有本机实际输入证据。

完整待验项见 [覆盖审计](coverage.md) 和 [实机操作单](manual.md)。物理多屏／混合 DPI、UAC、Narrator、系统／Explorer 重启、干净环境与独立易用性等仍未由本轮证明。功能验收完成后，再按用户约定集中优化外观和交互。
