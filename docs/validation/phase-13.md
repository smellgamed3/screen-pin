## 范围与方法

此前 Brave／VS Code 的最大化捕获与恢复使用配置界面命令，普通精度循环也使用 GUI 路径；已有真实热键主要覆盖文件对话框／全屏拒绝与独立 fixture。本轮给 [应用脚本](../../scripts/application-smoke.ps1) 增加可选 `-HotkeyStates`，由实际 SendInput Ctrl+Alt+F10／F9 验证普通、最大化和手动还原。

- 每款应用先用真实 F10 保存普通预设，实际移动后用真实 F9 恢复，连续采集 50 次。每次输入前核对唯一 profile、PID、标题和实际前台；输入后与等待中持续核对窗口归属及前台，偏离测试目标即停止进一步输入。
- 每次 F9 前通过自有 GUI 刷新完成并清除旧成功反馈，要求窗口确实偏离预设；恢复须同时匹配 DWM 可见边界和本次明确成功结果。恢复后的配置哈希不变，反馈仍为应用默认范围，前台保持原窗口。
- 普通矩形下最大化后，用真实 F10 保存最大化预设，采集前后均为最大化；手动还原并移动，再用真实 F9 恢复最大化。之后手动还原须回到原普通矩形；再用真实 F10 替换为普通预设，从最大化用真实 F9 恢复普通状态。
- 最大化、手动还原和移位使用明确目标的原生 API；最小化拒绝仍是原有 GUI 路径。窗口位置采集前后状态检查不能证明完全没有瞬时闪烁，相关门槛仍保留。

计时从已验证按键封装前开始，直到可见边界和新的成功反馈同时匹配；包含进程归属核对、输入封装和 10 ms 轮询开销，不当作纯 Win32 分发耗时。50 次普通恢复单独计算 p95，并要求 ≤300 ms。最大化两次转换单列，不混入普通 p95。

## 复现与边界

```powershell
pwsh -NoProfile -File scripts/application-smoke.ps1 -OutputDir artifacts/apps-phase-13-release -PrecisionCycles 20 -ExtendedStates -TemporaryDialogs -Fullscreen -HotkeyStates -HotkeyCycles 50
```

按 [构建入口](phase-6.md#回归与复现) 准备 Release；在 PowerShell 7 的正常桌面顺序运行。仅使用独立应用 profile、独立 Screen Pin 配置和唯一标题的本地文档；不操作既有用户窗口，不修改实际 HKCU Run，不结束按进程名匹配的共享宿主。运行期间避免切换窗口；现有实例或前台归属不符会拒绝真实输入。

这是本机单屏、96 DPI、默认任务栏、普通权限及所列版本的证据。物理多屏／混合 DPI、跨屏和自动隐藏任务栏、瞬时闪烁、最大化异步切焦、真实 UAC、Narrator、字体／高对比度、系统／Explorer 重启、干净 Win11 和独立首次使用仍按 [实机操作单](manual.md) 保留。浏览器／编辑器动态标题规则也未在本轮补齐。整体目标保持活动；外观与交互集中优化及其回归安排在功能验收之后。
