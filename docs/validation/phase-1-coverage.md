## 审计发现及当前修复状态

以下保留最初发现的因果，并按本次实际重读的源码及报告更新状态。源码修复已经完成的项目不再列为“未实现”；仍缺真实环境证据的部分继续标为待验证。

1. **请求最初没有窗口身份世代基准，影响 F03。已修复并有受控探针证据。** 原来仅传 HWND／PID，worker 采样前的同进程重建可能被接受。现在 WindowSummary／Snapshot 和窗口请求携带 token；热键触发或窗口列表建立自有 named property 世代，`Controller::capture` 在采样前核对，采样及后续操作继续校验，缺失旧标记不重新认领。退出清理只删除自有且值相符的 property。最新探针证明错误 token、同进程销毁重建的旧 token 被拒绝，清理保留无关属性；本次 OS 没有实际复用同一 HWND 数值，因此不声称该系统分配事件已实测。
2. **恢复纠偏原来使用旧拓扑，影响 F03／F06。源码已修复，物理拔屏待验证。** 原来两次延迟纠偏只检查窗口。现在首次外部写请求、每次纠偏及确认成功前重新枚举并比较完整拓扑和目标工作区，变化时阻止尚未发送的操作；已发送异步请求仍可报告未确认。纯测试覆盖增减屏幕、非目标变化及目标工作区变化，不代替真实拔屏。
3. **恢复配置入口可能绕过交接后的写入锁，影响 F12／F15。已修复并局部验证。** 审计时 `ConfigStore::replace_protected` 检查交接子状态但未要求持有 `lock`；现已在入口要求持有锁，允许“配置保护但持锁”的正常恢复。测试通过私有路径模拟认证 child，验证原实例释放 writer 后 reset／recover 均拒绝、主／备份字节不变、不生成 preserved 副本；child 持锁时 parent 不能重新获锁，child 退出后恢复可用。当前存储共 10 项测试通过，包含此回归和下述跨进程启动 reservation 验证，仍不代替真实 UAC。
4. **托盘创建结果原来未纳入接管就绪，影响 F15／F16。源码已修复，故障交接待实测。** `tray_add` 现在检查真实 BOOL 并维护 tray_ready；交接子实例托盘未就绪就拒绝确认接管。普通启动失败时显示可操作界面，支持刷新重试；Explorer 重建分支也检查结果。真实 Explorer 故障与 UAC 组合仍无运行证据。
5. **普通实例原来缺少激活提权实例的消息通道，影响 F16。源码已修复，真实完整性边界待验证。** 初始化只对无配置写入参数的 `SHOW_MESSAGE` 与 `TaskbarCreated` 调用受限 `ChangeWindowMessageFilterEx`，不放行其他业务消息。已有同权限 GUI smoke 仍不能替代实际高低权限重复启动或 Explorer 重启。
6. **部分关联路径原来一律全局暂停，影响 F04／F05。已实现并有逻辑断言。** 唯一完整 inventory 通过强证据及二分图匹配确定旧方案时，可选择该活动方案，但只发布已确认的显示器绑定；歧义目标不猜测映射、不持久化半完成关联。13 项拓扑测试包括已确认目标保持可用、仅型号及数量不能选旧方案。仍需真实多屏验证这一路径。
7. **先建特定规则后原来缺少显式新建默认入口，影响 F01。领域、控制器和 GUI 均已接入并有最终 Release ZIP GUI 证据。** `Engine::create_default` 保留既有规则，已有默认时拒绝，Remember 语义不变。17 项领域测试包含该操作的撤销及失败回滚。12:46:32 解压 ZIP GUI smoke 验证仅在有规则但无默认时出现次要按钮，显式捕获新增默认而保留所有规则，创建后按钮消失。
8. **交接 writer 空档原来可能让第三次普通启动抢锁，影响 F15。已修复并有真实多进程回归。** 原来 main 先尝试打开 store，只有 writer 冲突才激活既有实例；parent 释放 writer 到 child 取得 writer 之间，普通第三进程可能先成功。现在增加贯穿实例生命周期的独占 `launch.lock`；只认证 child 可从可信 parent 复制句柄，且复核实际文件路径。交接只释放 writer，parent／child 共享的 reservation file object 始终存活。辅助进程证明交接空档第三进程被拒、首次并发仅一方成功、目录隔离，以及 parent 关闭后 child 保留启动权。真实高低权限 UAC 交接仍待验证。
9. **TaskbarCreated 广播原来可能重复 NIM_ADD 并误报失败，影响 F16。已修复并有真实 API 回归。** host 和 Settings 两个顶层窗口都处理同一广播时，第二次添加相同图标会失败并把 tray_ready 误设为 false。[最小探针](../../artifacts/native-tray-repeat-probe.json) 确认重复 ADD 为 false。现在只由 host 处理；原生测试移除自建图标后，分别以两种窗口消息顺序模拟广播，证明只重建一次、真实图标存在且退出删除。测试模拟图标丢失，没有重启用户 Explorer。

应用重新绑定、自启状态警告／修复入口及新关键字冲突预览也已接入。GUI smoke 已证明迁移确认范围、取消无变化、完整迁移与目标冲突拒绝，关键字预览不写盘且说明重叠胜出规则，以及移动程序后的自启警告和修复按钮。该脚本刻意没有改写真实自启注册值，因此自启修复后的实际登录启动仍待验证。

## 实际缺少的外部验证条件

- 已有探针只显示一台显示器，缺少物理双屏／同型号双屏、不同 DPI、扩展坞及换线环境。模拟 Rect 可以证明计算，但不能证明这些设备身份和系统行为。

- 尚无独立新用户、Narrator、系统大字体、高对比度及不同缩放的完整使用记录。
- 尚无干净 Windows 11 x64 测试机／虚拟机的 ZIP 验收。真实应用目前只覆盖 Brave 155.1.97.59／VS Code 1.130.0 的普通主窗口 GUI 路径，未覆盖 Explorer、Terminal、管理员终端、对话框和打包应用升级。
