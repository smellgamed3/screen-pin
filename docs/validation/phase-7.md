## 实际操作与结果

目标 A 与观察窗口 B 在同一测试进程的不同 UI 线程。先以真实 SendInput F10 保存 A，再暂停 A；真实 F9 提交后，观察设置页刷新按钮禁用，确认操作已开始，才主动将前台切至 B。全过程核对窗口归属和实际前台，外部切焦即停止后续输入。

| 场景 | 直接结果 |
| --- | --- |
| A 暂停 1.2 秒，处理期间按真实 F10，然后切至 B | 忙时 F10 明确拒绝；恢复返回“暂无法确认”，没有排队更新。A 恢复响应后接收原先的延迟放置，回到已存位置；B 边框和配置哈希保持不变 |
| A 暂停后销毁，在同一线程重建同进程、同类名、同标题窗口 | 销毁前直接读到操作仍忙；替代窗口保留故意设置的不同位置和尺寸，B 与配置不变。随后对新窗口执行真实 F10／F9 可正常捕获及恢复 |
| A 暂停后关闭，B 留在前台 | 关闭前直接读到操作仍忙；结果未冒报成功，B 与配置不变。操作槽释放后，显式选择 B 的 GUI 捕获／恢复可用 |

同一单调时钟记录“观察忙碌 → 前台已切换 → fixture 动作完成”：三例分别为 **73.481 → 82.295 → 1216.448 ms**、**71.750 → 87.486 → 194.184 ms**、**75.302 → 90.811 → 186.995 ms**。关闭／重建前还由 fixture 直接检查禁用状态，避免只凭固定延迟推断重叠。暂停 1.2 秒的场景恢复操作提前返回，fixture 恢复时槽已释放，记录为 false 符合预期。

三例等待结果期间分别取得 15／8／8 次 host 与设置窗口响应样本，结果等待约 240／116／109 ms。该等待从切至 B 后开始，不能作为输入到反馈的端到端延迟，也不替代性能分布。

扩展共享辅助代码后补跑 [原有热键回归](../../artifacts/hotkeys/hotkey-20261017T061943103Z-ba4cb364/report.json)：**20 次完整循环、最大边界误差 0 px**；可见匹配 p95 15.093 ms，明确完成反馈 p95 32.489 ms。无变化不写、重复按下抑制、前台保持和正常退出通过。报告中的辅助代码哈希与竞态检查一致。

## 测试修正与边界

准备阶段曾遇到设置控件尚未创建、以及测试程序过早判断切焦失败；失败报告保留在 `artifacts/races`，不计入通过结果。现在等待控件就绪，并对预期窗口之间的切换有界观察实际前台。跨输入队列的激活具有异步部分，不能要求 SetForegroundWindow 返回后立即读到目标，参见 [Microsoft 的说明](https://devblogs.microsoft.com/oldnewthing/20161118-00/?p=94745)。未使用 AttachThreadInput 或其他前台限制绕过方式。

本轮替代窗口的 HWND 数值与原窗口不同；**没有强制或证明 OS 复用同一 HWND 数值**。也未覆盖物理拔屏、编辑与热键交错、最大化切焦时序、所有实际应用的异常行为。已经发出的放置可能在原目标恢复响应后生效，“未确认”不表示成功取消。完整待验项继续见 [覆盖审计](coverage.md) 和 [实机操作单](manual.md)。

## 复现

先按 [阶段 6 的构建与回归入口](phase-6.md#回归与复现) 准备 Release 和 `accessibility_probe.exe`，退出已有 Screen Pin，再依次运行：

```powershell
pwsh -NoProfile -File scripts/race-smoke.ps1
pwsh -NoProfile -File scripts/hotkey-smoke.ps1 -ExePath target/release/screen-pin.exe -OutputDir artifacts/hotkeys -Cycles 20
```

脚本需 PowerShell 7，在正常桌面会话运行；输入期间勿操作其他窗口。只清理核对归属的自建实例和窗口，不重启 Explorer、系统或触发 UAC。本轮没有产品源码改动，无须重复构建同一二进制；此前 62 项测试及严格 Clippy 的证据仍见阶段 6。
