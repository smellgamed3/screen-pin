## 首轮失败与诊断

首轮 `applications/application-smoke.json` 保留失败：Brave 已完成 GUI 基本恢复、20 次精度循环（最大 0 px）及九条状态检查，随后普通真实热键的 p95 ≤300 ms 断言失败。原脚本只在函数成功返回后保存该组分布，因此失败报告缺少具体 p95 和逐次耗时；不能用复测数据回填首轮，也不能据此确认超标幅度。脚本停止后续输入，自建 Brave／Screen Pin 正常退出，VS Code 未启动。

原测量从输入包装函数之前开始，包含其进程归属／独立 profile 校验、真实按键、实际 DWM 边界和新的成功反馈确认。初步假设分别为预校验占时、窗口／反馈确认变慢、系统或应用波动。结束前台测试后，独立只读采样 50 次本地 CIM 查询，p95 约 204.517 ms；该进程与原 Brave 样本不同，这项观察不足以确定首轮原因。

保留的改进仅在测试工具：

- 每次成功恢复后立即追加 JSONL，后续预算失败仍保留已经完成的样本，并在报告中关联文件路径。
- 增加归属校验耗时、原生按键调用耗时和校验后的剩余确认时段。正式 `completion_ms`、计时起点、50 次采样及 300 ms 断言不变；全部原有身份／前台检查保留。
- 可选计时参数的原调用方式、无额外管道输出、拒绝身份后不进入输入边界，经提取真实函数的无 GUI 边界检查通过。该检查使用惰性边界替身，不计为产品验收。
